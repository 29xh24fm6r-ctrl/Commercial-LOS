### LOOKUP_TARGET_MISMATCH / NAVIGATION_PROPERTY_MISMATCH

| # | item | evidence | impact |
|---|---|---|---|
| C-10 | Generated `@odata.bind` keys are typed as bare `string` with an untyped `object` expansion — **no compile-time target-table enforcement** on ANY lookup (`cr664_ChangedBy`, `cr664_AssignedBanker`, `cr664_StageReference`, `cr664_StatusReference`, `cr664_PrimaryWorkspace`, `cr664_Role`, `cr664_Deal`, …) | `Cr664_*Model.ts` lookup keys | This is **why the systemuser-into-cr664_user defect compiles** (Phase 187F). Nav-property **casing** is consistent (`cr664_ChangedBy@odata.bind`, etc.); no casing mismatch found.

**No `OPTION_VALUE_MISMATCH` for the audit table.** The numeric constants the emitters use are correct.

## Summary

| category | count | severity |
|---|---|---|
| DATA_SOURCE_NOT_REGISTERED | 1 (C-1) | high (identity actor table) |
| RUNTIME_DEPENDENCY_NOT_AVAILABLE | 4 (C-2..C-5) | high |
| LIVE_ONLY | 3 (C-6..C-8) | medium |
| GENERATED_ONLY | 1 (C-9) | low |
| LOOKUP_TARGET_MISMATCH / NAV | 1 systemic (C-10) | high (root cause of 187F defect) |
| ENTITY_SET_MISMATCH | 0 | — |
| REQUIRED_FIELD_MISMATCH | 0 | — |
| OPTION_VALUE_MISMATCH | 0 (cleared) | — |

**The single structural break is the identity sub-graph** (`cr664_user`, `cr664_workspacetype`,
`cr664_userrole`, `cr664_workspacecontext`): generated as a service (only `cr664_users`) or not at
all, none registered as runtime data sources. The app correctly avoids `Cr664_usersService` and
synthesizes the required `cr664_ChangedBy` bind from the registered `cr664_platformusers` bridge.

**The single systemic code risk is C-10** — untyped `@odata.bind` keys let any caller bind the wrong
target entity set, which is exactly the Phase 187F defect (12 emitters bind `/systemusers` into a
`cr664_user` lookup). Remediation must add a metadata-backed bind guard + target-assertion tests,
because the generated SDK provides no protection and must not be hand-edited.
